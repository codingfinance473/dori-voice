## 2. 가격 정확성 규칙 (3판 핵심 — 바꾸지 않는다)

1. **사람이 숫자를 옮겨 적지 않는다.** 브라우저에서 `capture.js` 로 공식몰을 읽은 기록(주소·읽은 시각·서명)만 쓴다. 서명이 한 글자라도 안 맞으면 받지 않는다(서명 v2는 할인·세금 판정 칸까지 묶는다).
2. **한 가격 = 읽는 방식이 다른 기록 2개 이상이 같아야 통과.** 화면 가격(product) + 같은 주소를 다시 받은 서버 원본 데이터(state, 크롬 자동 번역 영향 없음) + 검색 목록(list).
3. **할인 표시가 보이면 정지**(화면 문구·서버 promo·가격 플래그). 세금 포함 여부도 서버 데이터(taxPolicy)로 확인.
4. **환율은 한국은행 ECOS 매매기준율(서울외국환중개 고시)만.** 기사 속 마감 환율은 쓰지 않는다(2판의 843.79원이 이 경우였다 — 공식 고시는 846.12원). API는 한 번에 10건이라 기간 안 영업일이 더 많으면 마지막 쪽을 다시 받는다(안 그러면 오래된 환율이 쓰일 수 있었다). 화면에 "카드 결제액과는 달라요"를 둔다.
5. **확인 시각을 화면·설명에**: 위 칩 "가격 10/24 01:33~01:46 확인", 영수증, 품목 줄(01:43 확인), 끝 화면, 설명란. 증거는 마지막 확인 후 **24시간**까지만 영상에 쓴다(계산·렌더·qa가 다시 검사).
6. **계산**: Decimal, 원화 1원 단위 반올림(0.5 올림), % 정수 반올림. 영수증 끝수·환급 수수료로 달라지는 세금·환급은 "약".
7. **제도 숫자·문장**(면세 시행일·90일·5,000엔, "세금 포함 가격으로 결제", "출국 때 세관 확인 뒤 소비세 상당액 환급")은 정부 원문에서 문구를 기계로 찾은 기록이 있어야 쓴다. 원문에 없는 말(환급 수수료 등)은 쓰지 않는다.
8. **화면 숫자 점검**: 0.2초마다 화면의 모든 숫자가 계산표·원문 숫자에서 왔는지, 품목 카드가 계산표와 글자 그대로 같은지, 숫자가 스티커·도장·말풍선에 가려지지 않는지 본다. 숫자가 세어 올라가는 연출 없음(멈춘 화면에도 틀린 숫자가 없게).
9. **목소리**: 자막 숫자와 대사 숫자를 합성 전에 대조, 받아쓰기에 숫자가 안 들리면 어림수로 바꾸지 않고 멈춘다(사람이 듣고 승인하면 `voice.accept`).
10. **배경 통계도 최신으로**(2026-10-29): 방일 관광객 수·카드 결제액·환율 추이처럼 가격 밖의 숫자도 오늘 기준 가장 최근 발표를 쓰고, 기관 + 기준 기간을 화면에 적는다.

## 6. 목소리·배경음 (2026-10-24 밤 개편)

요청: "목소리가 남자 같다 → 햄토리처럼 발랄하고 귀엽고 듣기 싫지 않게", "배경음은 산뜻하고 넘기기 싫지 않은 멜로디로".

- **왜 남자 목소리였나**: Supertonic-3 기본 화자 10명을 재 보니 0~4번이 여성 계열(평균 음높이 186~232Hz), 5~9번이 남성 계열(96~147Hz). 2판 기본 B는 5번+8번(약 150Hz)이었다.
- **새 기본 E**: 화자 2번(억양 폭이 가장 넓음, 12.4반음) + 캐릭터 톤(Praat 'Change gender': 음높이 278Hz, 성도 10% 짧게, 억양 1.15배) → 실측 음높이 약 275Hz, 억양 폭 12.5반음. 속도 1.08, 숫자가 든 줄은 0.92배(2판과 비슷한 빠르기).
  후보 E1(262Hz, 차분한 쪽) · E3(292Hz, 더 작고 어린 느낌) · B(2판). 비교 영상 「도리_목소리_후보.mp4」(1번 E1 · 2번 E · 3번 E3). 모모(화자 1번)와 다른 화자이고, 특정 성우·캐릭터 목소리를 흉내 내지 않는다.
- **숫자 안전장치**: 속도 1.10에서는 11줄 중 3줄의 숫자가 받아쓰기에서 뭉개졌다 → 숫자 줄만 천천히. 숫자는 합성 소리와 다듬은 소리(압축·울림) 두 번 다 받아써져야 통과,
  완성 믹스(배경음·효과음을 깐 소리)에서도 줄마다 다시 받아써 덜 들리면 그 줄 배경음을 5dB씩 더 낮춰 다시 섞는다(qa 「배경음 위 숫자 받아쓰기」). 받아쓰기가 '37%'처럼 기호로 적어도 같은 말로 본다.
- **배경음 「도리 산책」**(직접 작곡·합성한 원곡, `music.py`): 사장조, A = I–V–vi–IV · B = IV–V–iii–vi(왕도 진행), 우쿨렐레 스트럼(현 합성, 조율 오차 1센트 이내)·통통 튀는 베이스·마림바 멜로디(2마디 동기)·글로켄 반짝임·가벼운 킥·박수·셰이커.
  편 길이에 맞춰 템포를 골라(EP01 117 BPM) 마지막 대사 바로 뒤에 끝 화음. 2판 로파이는 `music.style: "lofi"`.
- **섞기**: 쉬는 동안 목소리보다 11dB 아래(멜로디가 들리게), 말하는 동안 8dB 더(1.2kHz 위 4dB·숫자 줄 2dB 더). 줄 사이 짧은 쉼(0.42초)에서는 붙잡아 출렁이지 않고 장면 사이에서만 올라온다.
- 소리 처리(2판 그대로): 저역 정리, 먹먹한 중저역 −1.5dB, 압축, 디에서·고역 셸프, 옅은 방 울림, 목소리 리미터, 마스터 미리 보는 리미터. 줄 사이 0.42초, 장면 사이 0.75초.
- 업로드 꾸러미: 다시 렌더해도 증거가 같으면 채운 제목·요약·해시태그를 유지한다(증거가 바뀌면 숫자가 달라질 수 있어 비운다).

## 6-1. 도리 목소리 C (2026-10-28 확정)

- 요청 흐름: 지금까지 후보가 다 별로 → 유료(ElevenLabs·타입캐스트)는 결제 싫음 → 본인 목소리는 두꺼워서 안 씀 → **무료로 귀엽고 거슬리지 않는 목소리를 찾아 만들기**.
- 방법: 오픈 모델 **Qwen3-TTS**(알리바바, Apache-2.0, 한국어 지원)를 사용자 비공개 저장소 `codingfinance473/dori-voice` 의 **깃허브 액션**에서 CPU로 돌린다(이 작업 공간은 허깅페이스·음성 API가 막혀 있음). 결제·API 키 없음, 비공개 저장소 무료 한도 매달 2,000분.
- 고른 과정: 설명문 6가지(소년·여자아이·애니 마스코트·포근·명랑한 꼬마·한국어 기본 Sohee) → 사용자가 2번(여자아이)과 3번(애니 마스코트) 사이를 원함 → 중간 4가지(A·B·C·D) → **C 선택**(중국어 설명 「介于甜美软萌的小女孩和活泼的动漫吉祥物之间…」, 음높이 약 399Hz, 받아쓰기 0.94).
- 고정: `voices/dori/ref.wav`(15.8초)+`ref.txt` → 매 편 **0.6B Base**가 따라 읽는다(시험: 음높이 343~439Hz로 C와 비슷, 6개 중 5개 숫자 통과 → 줄마다 3번 만들어 가장 또렷한 것). 1.7B는 깃허브 컴퓨터에서 3배 이상 느려 쓰지 않는다.
- 알아 둘 점: 깃허브 무료 컴퓨터는 매번 사양이 달라 속도 차이가 크다(같은 일이 7분~48분). bf16 가속이 있는 CPU(인텔 제온 8573C 등)면 빠르다. 생성 길이 상한(글자당 3프레임+60)으로 멈추지 않는 생성을 막고, 중간 결과도 올린다.
- 스킬: `voices.json` 기본 Q, `scripts/qwen_gh.py`(design·lock·say·대사 생성), `voice.py` 가 받아쓰기로 고른다. 예비 E(Supertonic-3).

## 8. 알아 둘 점 (운영)

- 브라우저로 같은 사이트를 빠르게 여러 번 열면 막힌다(유니클로 한국 검색이 16번째쯤 Access Denied) → 페이지 사이 4~5초, 막히면 그 사이트 멈춤.
